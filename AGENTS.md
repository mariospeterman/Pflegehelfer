# Pflegehelfer repository instructions

Read and follow [`agent.md`](agent.md), the active [`docs/PRODUCT_CONTRACT.md`](docs/PRODUCT_CONTRACT.md), the single canonical [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), [`docs/PRODUCT_EXPERIENCE.md`](docs/PRODUCT_EXPERIENCE.md) and [`docs/WORKFLOWS.md`](docs/WORKFLOWS.md) before changing code.

Non-negotiable: one coherent role-aware GenUI/chat/voice clinical coworker and one working session with multiple explicitly scoped conversations: the employee's general assistant, private patient-and-encounter assistant threads, separately authorized patient-team threads, and governed department/direct threads where enabled. **Conversational outside, structured inside:** staff never sees proposal/schema terminology or a form wizard; the assistant responds naturally first and shows only the minimum useful review UI. Contact-style patient tabs are read/query lenses over the same records and command pipeline, not workflow-owning dashboards or duplicate applications. Models may interpret/compose bounded presentation; deterministic server code alone validates, authorizes and executes. Preserve negation, uncertainty, historical/occurrence time, partial/deferred work, interruption and corrections; never infer an unstated clinical action, completion or billable activity.

The PostgreSQL workday, its handover-ID/version-bound patient acknowledgements, actor-owned episodes and explicit receiving-shift transfer receipt are the only production handover/responsibility authority. Completed episodes and transferred shifts are final; one planned responsibility cannot be duplicated. Do not reintroduce seeded or provider-document handover state as an executable fallback. Generic team-role addressing must stay a role queue until a named recipient claims it; never select the first user in a list. High-assurance measurements are not current clinical facts until an independent authorized reviewer countersigns them.

Every message, draft, attachment, model request and recent-context window must remain bound to its authorized thread, patient/encounter where applicable, and captured context revision. Private assistant drafts never enter a team thread without explicit audience review and publication. Every entry path, including direct typed endpoints, must independently enforce the same medication/treatment boundary, task-completion evidence rules, observation time/range/high-assurance policy and provider-write protection; a UI route or model classification is never the safety boundary.

Site configuration may only narrow centrally reviewed role permissions. Every FHIR identity, tag, cleanup and migration is institution/site scoped. Never read an unscoped legacy checkpoint without an explicit site-and-digest-bound migration manifest, an exact digest-bound legacy-resource inventory and an elapsed legacy-receipt retention gate. High-assurance values must not enter episode/task completion evidence through a parallel free-text note; derive completion evidence only from current, certain structured work and independently accepted observations. A successful `/models` response is connectivity evidence only; model and ASR acceptance require real, non-writing synthetic contract tests.
