# Product experience

## Promise

A staff member opens Pflegehelfer and meets one calm clinical coworker. One work session preserves the day while a general assistant and contact-style patient workspaces keep conversations explicitly scoped. It knows the authorized role workflow, starts with what changed, requests explicit patient context when needed, materializes the smallest useful interactive component, and keeps follow-up visible until closed. Conventional clinical pages are exceptional.

All demo content belongs to **Tertianum Kronenhof · Demo** and is fictional.

## Shell and rhythm

The shared conversation shell with docked text/voice composer is central. A compact header shows organization, actor/role, connectivity and synchronization. Desktop has a narrow sidebar; mobile puts the same controls in a drawer. My assistant, patient contacts, team and history select persistent scoped conversations without ending the work session. A patient workspace identifies “Pflegehelfer zu [name] · Privater Assistenzchat”; its Chat, Profile, Timeline, Values, Team and More lenses use the same source records. Team is a visibly separate authorized audience. An active patient safety strip always shows room, name, birth date, encounter/MRN and the state of permitted warnings; missing data is never phrased as a negative finding.

The coworker states the current step, shows source-linked facts/work, accepts natural language/voice or component input, shows exact identity/diff/evidence for drafts, and gives a receipt distinguishing local acceptance from external acknowledgement. Mentions, alarms, replies and conflicts enter the appropriate authorized thread proactively. Private drafts never enter a shared team audience automatically. One sentence may yield multiple separately reviewable candidates.

## Team and voice

`@name`/`@role` create visible recipient obligations with sent, acknowledged, answered, escalated and closed states, linked to patient/workflow/source/resulting task. The assistant may draft/route but cannot impersonate an answer.

Voice uses browser demo recognition or configured local ASR. Transcript remains editable. Safety-critical identity, dose/unit, values, negation, time/laterality are individually confirmed. Edits invalidate old receipts; raw audio is erased.

## Components and appearance

Allowed components include patient picker/context, delta handover, task queue/item, vital result/trend, documentation draft/diff, bounded form, team thread/mention, approval, sync receipt/conflict, workflow progress, safety notice and approved-policy answer. No arbitrary HTML/script/URL/tool call/model endpoint is rendered.

Use semantic white/black/deep blue; red for safety, amber for pending/conflict, green only confirmed success. Support system/light/dark, 44px bedside targets, keyboard/focus, reduced motion and WCAG 2.2 AA. Mobile has one active conversation, a drawer and compact patient lenses; it never has a second workflow-owning module bar.

## Failures

Offline approvals/sends are disabled and never silently queued. AI failure leaves deterministic workflows available. Medplum/provider failure is explicit and never shown as acknowledged success. Invalid/incomplete model streams expose no executable control. Context/version changes close stale review and explain why.

## Acceptance

A nurse can receive handover, choose patients, inspect facts, document work/vitals, handle an alarm, ask a physician, review actions, see synchronization and prepare handover without finding a module page. A physician receives/answers in the same interaction model. Authorized state survives refresh/restart according to policy.
